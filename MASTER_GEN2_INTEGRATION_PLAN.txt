==================================================
1. ARCHITECTURAL OBJECTIVE
==================================================
Build one coherent close-to-cover continuity pipeline in which four separate questions have four separate owners:

1. COVER LEASE AUTHORITY
   Is Duo currently authorized to mutate/hold the physical cover route, and is the shell observation current?

2. COVER READINESS
   Is the lease-owned physical cover presently represented by a fresh app-visible logical route that is ready to host continuity content?

3. FRAME PROVENANCE
   Do the frozen pixels belong to THIS exact close cycle rather than merely being recent and correctly sized?

4. PRESENTATION OWNERSHIP
   Did THIS exact authorized content attempt actually reach draw / frame-commit / SurfaceFlinger presentation evidence, rather than a stale attempt producing a callback?

These are complementary facts. Do not merge them into one mega-state-machine or one generic generation variable.

==================================================
2. REQUIRED IDENTITY LAYERS
==================================================
A. CONTROLLER / TRANSITION POLICY
- transitionGeneration remains Fold7ContinuityController-owned.
- It identifies policy transitions/actions.
- Do not reinterpret it as global lease/frame/presentation identity.

B. SHELL COVER LEASE AUTHORITY
- shellSession (opaque per DuoShellService process)
- shellRevision / coverMutationRevision (monotonic at serialized mutation boundary)
- leaseId
- leaseEpoch
- ownerGeneration
- stable physical cover id

C. READINESS / MUTATION REQUEST
- transitionGeneration
- exact accepted cover lease token
- requestSequence / ticket identity
- current topology observation identity
- stable physical cover id

D. FRAME PROVENANCE
- serviceEpoch
- closeCycleId (stable across one deliberate close cycle)
- captureSequence
- contentLeaseId or equivalent immutable frame identity
- source geometry/panel
- request/capture/completion timing metadata
- capture source and timestamp quality

E. PRESENTATION
- serviceEpoch
- closeCycleId
- contentLeaseId
- hostEpoch / hostInstance identity
- presentationAttemptSequence
- immutable destination identity
- render path (FROZEN_VIEW or LIVE_MIRROR)

IDENTITY RULE
It is acceptable for these values to be Longs internally, but they must remain semantically typed/separate. A later callback is accepted only by the owner whose exact identity it carries.

- reassert request completion carries exact ticket identity

GATE BEFORE PHASE 3:

- no regression in native Samsung handoff

PHASE 3 — FROZEN FRAME PROVENANCE GEN2
Goal: prevent a previous fold-cycle bitmap from becoming the deterministic current-cycle continuity frame just because it is young.

P0:
- introduce continuity-specific frame store/lease; avoid changing generic SnapshotCache semantics unless necessary
- begin a new closeCycleId once per deliberate close cycle
- keep closeCycleId stable through CLOSING_INTENT -> PREWARM -> READY_HIDDEN -> COVER_VISUAL
- invalidate cycle on reversal, native-cover takeover, service restart, destruction
- attach exact cycle/provenance metadata to captures
- accept frozen frame only for exact serviceEpoch + closeCycleId + current capture sequence/content lease
- capture failure/timeout must not silently resurrect a prior-cycle continuity frame
- retain live mirror/native fallback when no current-cycle frozen frame is proven

IMPORTANT
Do not make readiness depend on frozen-frame availability. Ready destination and eligible content are separate facts.

GATE BEFORE PHASE 4:
- provenance tests green
- secure-content / capture-failure / delayed-capture tests green
- close-open-close stale frame test green
- build green

PHASE 4 — PRESENTATION LEASE GEN2
Goal: attribute draw/commit/present evidence to the exact authorized content attempt.

P0:

P1 frozen path:

- record transaction committed/completed/present-fence evidence with the same immutable presentation identity
- first integration is observation-only; do not block visibility waiting for instrumentation callbacks

P1 telemetry:

- preserve latest hinge sample only as observation/correlation, not ownership

P2 only after field evidence:
- add recovery policy only if missing/late presentation evidence actually correlates with user-visible failure
- no blind timer/retry loops

4. CROSS-LAYER INVARIANTS
==================================================
1. Stable physical panel identity is never a logical display ID.
2. Logical display IDs are freshly resolved, validated, and disposable.
3. User's real Android task stays on normal/default display.
4. No raw physical-panel OFF command is introduced.
5. Samsung-native handoff remains authoritative near closed/native topology.
6. Opening and closing remain asymmetric.
7. Reversal is mandatory; stale async work must become inert.
8. Duplicate callbacks/commands are expected and must be idempotent/fenced.
9. Keep 174° prewarm, 135° visual, and established reversal/hide thresholds unless direct measured evidence justifies a separate change.
10. Preserve 1.3.29 deterministic frozen-frame intent: do not restore live recapture underneath a stationary fold.
11. Preserve early-inner-wake infrastructure unless direct conflict is proven.
12. Keep Transition Lab; extend it rather than bypassing it.
13. "Committed" != "presented" != photons visible.
14. No subsystem may guess ownership from timing alone when an explicit token can exist.
