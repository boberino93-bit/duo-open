1. EXECUTIVE SUMMARY
==================================================

SUBSYSTEM CHOSEN
Fold7 deterministic frozen-continuity-frame provenance and lifecycle between PanelEngine/SnapshotCache and DisplayMirrorHost.

WHY CURRENT main MADE THIS THE HIGHEST-VALUE TARGET
CURRENT main 8f844ba8aadd8417a92ec8b568288fd0dd9e06e3 already contains substantial Gen2 work for hinge-poll identity, mirror ownership, cover-panel lease ownership, route reassertion, deterministic frozen rendering, early inner wake, and Transition Lab instrumentation. Two additional R&D packages supplied during this investigation were independently verified and rerun: Cover Readiness Gen2 and Cover Lease Protocol Gen2. Those packages already go deep on topology/readiness timing and app↔shell lease identity/order, so repeating either area would be duplication.

The remaining concrete weakness is inside the new 1.3.29 frozen-frame path. FoldOverlayService obtains the continuity frame from the generic SnapshotCache using only:
- panel kind = inner;
- expected geometry = 1968x2184;
- age <= 10,000 ms.

SnapshotCache itself stores only bitmap + insertion uptime, keyed by Boolean inner/cover. It does not record which physical close cycle produced the image. DisplayMirrorHost then accepts the returned bitmap if dimensions match and it is not recycled. Therefore the continuity host has no proof that a candidate frame belongs to the current close transition.

DOMINANT LIMITATION
Frozen-frame eligibility is based on recency, not ownership/provenance. A bitmap captured during an earlier fold can remain eligible for a later close cycle. If the current-cycle capture is unavailable, delayed, or fails, the stale-but-young prior frame can suppress the live-mirror fallback and become the cover continuity frame.

GENERATION-2 DIRECTION
Introduce an explicit transition-scoped Continuity Frame Lease:
- a service/process epoch;
- a stable closeCycleId that spans CLOSING_INTENT -> PREWARM -> READY_HIDDEN -> COVER_VISUAL;
- capture sequence identity;
- source geometry / panel identity;
- capture source and timestamp-quality metadata;
- capture request start and capture/completion timestamps;
- exact-cycle acceptance in a small deterministic ContinuityFrameLeaseStore;
- invalidation on reversal, native-cover takeover, service restart, and destruction;
- no reuse of a prior-cycle frame merely because it is young;
- existing live-mirror/native fallback remains available when no current-cycle frozen frame is proven.

This is intentionally NOT a proposal to reduce FOLD7_FROZEN_FRAME_MAX_AGE_MS. Tightening 10 seconds to some arbitrary smaller constant would remain a temporal heuristic. The Gen2 design makes frame ownership explicit.

STRONGEST EVIDENCE
1. FINAL main SnapshotCache keys entries only by panel kind and stores bitmap + insertion uptime.
2. FINAL main FoldOverlayService permits the frozen continuity provider to return an inner frame up to 10,000 ms old.
3. FINAL main DisplayMirrorHost validates only bitmap validity/dimensions before binding the frozen frame; no fold-cycle token is checked.
4. FINAL main PanelEngine onCaptured() writes the latest capture into the generic cache, while capture failure/timeout paths do not invalidate the prior cache entry.
5. Android AccessibilityService.ScreenshotResult exposes the actual screenshot timestamp in the SystemClock.uptimeMillis() domain, allowing exact capture-time provenance for that path.
6. Android documents ERROR_TAKE_SCREENSHOT_SECURE_WINDOW, confirming that capture failure can be a legitimate runtime condition rather than only an exceptional bug.
7. A source-faithful age-only baseline model deterministically accepts a previous-cycle frame when it is <10 s old and dimensions match.
8. The Gen2 pure-Kotlin provenance model compiled and passed 15/15 deterministic tests including 100,000 fixed-seed randomized operations.

CONFIDENCE LEVEL
HIGH for the source-level provenance gap and the deterministic model properties.
MEDIUM for the practical frequency with which a stale prior frame is currently selected on a physical Fold7 because that requires field traces.
LOW/UNKNOWN for any claim that this specific gap is the dominant cause of an existing user-visible glitch. Device evidence is required.

LARGEST REMAINING UNKNOWN
How often a close reaches COVER_VISUAL before a current-cycle inner frame is available, and whether real Fold7 capture failures/timeouts leave an eligible prior frame often enough to be visible. FOLD7 FIELD VALIDATION REQUIRED.

4. CURRENT IMPLEMENTATION
==================================================

IMPORTANT FILES / CLASSES

ENTRY POINT / EVENT SOURCE
Physical hinge samples enter FoldOverlayService.onHinge(angle).
FoldOverlayService calls continuity.onHinge(angle) first, then each PanelEngine.onHinge(angle).
This ordering is important: the continuity state machine can identify closing intent before a PanelEngine processes the same hinge sample, but a PanelEngine may also have started capture on an earlier, smaller movement before deliberate close intent was fully established.

CURRENT CONTINUITY STATE OWNERSHIP
Fold7ContinuityController owns fold state and a state-transition generation. Its generation increments on every state transition, not once per complete close cycle.
Relevant closing states:
OPEN_INNER / INNER_HANDOFF
-> CLOSING_INTENT
-> COVER_PREWARMING
-> COVER_READY_HIDDEN
-> COVER_VISUAL
-> NATIVE_COVER
with reversal paths back toward INNER_HANDOFF/OPEN_INNER.

Because controller.generation increments across those internal states, it is not itself a stable frozen-frame cycle identity.

CURRENT SNAPSHOT CACHE
SnapshotCache stores:
Entry(bitmap, at)
inside HashMap<Boolean, Entry>, where Boolean identifies inner vs cover.
put(innerPanel, bitmap) overwrites that panel-kind entry.
get(innerPanel, width, height) checks:
- entry exists;
- bitmap not recycled;
- dimensions equal requested size;
- age <= SnapshotCache.maxAgeMs.
No capture sequence, transition/cycle ID, source display physical identity, capture timestamp quality, or service epoch is retained.

The generic SnapshotCache is constructed with SNAPSHOT_MAX_AGE_MS = 15 minutes for bridge behavior elsewhere.

CURRENT FOLD7 FROZEN FRAME PROVIDER
FoldOverlayService supplies Fold7ContinuityCoordinator with frozenInnerFrame lambda.
That lambda:
1. reads snapshots.ageMs(true);
2. requires age <= FOLD7_FROZEN_FRAME_MAX_AGE_MS;
3. requests snapshots.get(innerPanel=true,width=1968,height=2184).
FOLD7_FROZEN_FRAME_MAX_AGE_MS = 10,000 ms.
Therefore Fold7 continuity uses an additional 10 s age cap but no cycle ownership.

CURRENT CAPTURE PRODUCER
PanelEngine starts capture when its fold effect begins. Shizuku capture is attempted when configured/ready; otherwise AccessibilityService.takeScreenshot is used.
PanelEngine has captureGen/captureAttempt logic to prevent a late screenshot from mutating a newer PanelEngine phase.
That is useful local ownership, but it is scoped to PanelEngine's effect phase, not to DisplayMirrorHost's later continuity-frame selection.

On successful capture, PanelEngine.onCaptured(bitmap, ...) calls:
cache.put(innerPanel, bitmap)
then presents/replaces the fold overlay.

On capture failure/timeout, the prior SnapshotCache entry is not globally invalidated. Thus a prior successful inner capture may remain available to the continuity frozen-frame provider.

CURRENT DISPLAY MIRROR HOST
DisplayMirrorHost.bind(reason):
1. resolves root SurfaceControl;
2. freshly finds the 1968x2184 inner Display;
3. checks source logical ID != destination logical ID;
4. computes sourceKey from current logical source/destination and geometry;
5. calls tryBindFrozenFrame(...);
6. only if no acceptable frozen frame exists does it fall back to the live SurfaceControl mirror path.

tryBindFrozenFrame:
- calls frozenFrameProvider();
- rejects recycled bitmap;
- rejects wrong dimensions;
- otherwise binds it, makes frozenPaneView visible, and returns true.
It does NOT check when/why/which close cycle produced the bitmap.

CURRENT FROZEN FRAME LIFETIME
Once bound, the host keeps the bitmap reference until:
- sourceKey changes and clearFrozenFrame() runs; or
- host detaches.
For the same sourceKey, refresh() simply invalidates the existing frozen pane and returns; it does not replace the frozen frame with a later current-cycle capture. This is consistent with 1.3.29’s deterministic-frame intent, but it increases the importance of selecting the correct frame once.

CURRENT SHIZUKU CAPTURE
ShizukuBridge.capture(...) is blocking, returns Bitmap?, and returns null when the shell reports secure content or other failure. The current app-level return type discards request/capture/completion provenance beyond logging an elapsed millisecond duration.

CURRENT ACCESSIBILITY CAPTURE
AccessibilityService.takeScreenshot returns ScreenshotResult. Current code uses hardwareBuffer and colorSpace but does not consume ScreenshotResult.timestamp.
Official Android API documents getTimestamp() as screenshot time in milliseconds of non-sleep uptime from SystemClock.uptimeMillis(). This is directly compatible with the app’s existing monotonic timing domain.

CURRENT TEST GAP
Fold7ContinuityController tests cover state transitions but do not exercise bitmap provenance. No dedicated SnapshotCacheTest, DisplayMirrorHostTest, or PanelEngineTest was found at the expected test paths.

CAUSAL PATH
PHYSICAL HINGE SAMPLE
-> FoldOverlayService.onHinge
-> Fold7ContinuityController transition policy
-> PanelEngine.onHinge/evaluate
-> startEffect/startCapture
-> Shizuku or Accessibility screenshot
-> PanelEngine.onCaptured
-> SnapshotCache.put(innerPanel=true, bitmap)
-> later COVER_VISUAL / syncMirrorHost
-> DisplayMirrorHost creation/attach/bind
-> frozenFrameProvider
-> age <= 10 s + geometry check
-> tryBindFrozenFrame
-> View.onDraw canonical left-pane crop
-> cover presentation

RACE / OWNERSHIP BOUNDARIES
- PanelEngine capture is asynchronous.
- Controller state advances asynchronously with privileged prewarm completion.
- The generic cache persists across state transitions and fold cycles.
- Current-cycle capture can fail or arrive after the host asks for a frame.
- The host does not know whether the selected cached image came from the current cycle.
- Once a frame is bound for a stable sourceKey, current host refresh does not replace it.

7. HYPOTHESES / UNVERIFIED RISKS
==================================================

H1 — CURRENT-CYCLE CAPTURE SOMETIMES MISSES COVER_VISUAL
Hypothesis: a fast close, capture failure, or delayed waking-panel capture causes DisplayMirrorHost to request a frozen frame before the current close produced one.
Experiment: log closeCycleId, capture request/start/completion, provider query, selected frame ID, and COVER_VISUAL entry across slow/medium/fast closes.

H2 — STALE PRIOR-CYCLE FRAME IS PHYSICALLY VISIBLE
Hypothesis: when H1 occurs and a prior inner capture is <10 s old, the current implementation displays it on the cover.
Experiment: create two visually distinct app states A/B across consecutive closes <10 s apart; deliberately fail/delay B capture; capture 240 fps external video and Transition Lab frame IDs.

H3 — SHIZUKU CAPTURE TIME BOUNDS ARE TOO WIDE FOR SAFE ADOPTION OF A PRE-CYCLE REQUEST
Hypothesis: because current ShizukuBridge.capture returns Bitmap only, a request that began before close-cycle arming cannot prove its pixels were sampled after cycle start.
Experiment: extend shell response with request-start/completion uptime and, if available from capture API, actual capture/latch timing. Until then, fail closed for requests started before cycle start.

H4 — FAIL-CLOSED PROVENANCE MAY INCREASE LIVE-MIRROR FALLBACK FREQUENCY
Hypothesis: rejecting unproven cached frames can make some transitions fall back to the existing live mirror path more often.
Experiment: A/B log frozen-frame-hit rate, live-fallback rate, first-visible-frame time, and visual quality.

H5 — 10 SECOND WITHIN-CYCLE FRESHNESS MAY BE TOO PERMISSIVE FOR A PAUSED CLOSE
Hypothesis: an unusually long paused close could still use a frame that is old in human terms even though it belongs to the same cycle.
Experiment: pause the hinge at several angles for 2/5/10+ seconds then continue. Do not change the existing 10 s cap without measured evidence.

8. GENERATION-2 DESIGN
==================================================

DESIGN NAME
Transition-Scoped Frozen Frame Lease (TSFFL)

RESPONSIBILITY SPLIT
A. Fold7ContinuityController remains the owner of hinge intent/state transitions and all existing angle thresholds.
B. New ContinuityFrameLeaseStore owns only continuity-frame provenance/eligibility.
C. PanelEngine remains the renderer/capture consumer for the fold shader and may continue using the generic SnapshotCache for its own bridge behavior.
D. Fold7 continuity frame selection must stop reading an untyped Bitmap directly from generic SnapshotCache.
E. DisplayMirrorHost consumes a FrameLease (or equivalent immutable metadata+Bitmap object), not Bitmap? with no provenance.
F. Transition Lab records frame lifecycle metadata but does not influence acceptance.

NEW IDENTITY: serviceEpoch
Opaque per AccessibilityService lifetime (or equivalent process/session identity). Prevents a late capture from an old service instance from becoming eligible after service restart.

NEW IDENTITY: closeCycleId
A monotonic ID created once when deliberate closing enters a new close cycle. It remains stable through:
CLOSING_INTENT
-> COVER_PREWARMING
-> COVER_READY_HIDDEN
-> COVER_VISUAL
and is invalidated by:
- reversal back toward inner;
- native-cover takeover / close completion;
- explicit release/destroy;
- service restart.

IMPORTANT: do NOT use controller.generation directly for closeCycleId because controller.generation intentionally changes on every state transition.

FRAME PROVENANCE RECORD
Recommended immutable fields:
- serviceEpoch
- closeCycleId
- captureSequence
- sourcePanel=INNER
- width=1968
- height=2184
- captureSource=ACCESSIBILITY|SHIZUKU
- requestStartedUptimeMs
- capturedUptimeMs or bounded equivalent
- completedUptimeMs
- timestampQuality=EXACT_CAPTURE|REQUEST_BOUNDED
- Bitmap reference

ACCESSIBILITY TIMESTAMP RULE
Use ScreenshotResult.timestamp as capturedUptimeMs. Accept only when:
- serviceEpoch matches;
- closeCycleId is current;
- capturedUptimeMs >= closeCycleStartedUptimeMs;
- geometry is exact;
- captureSequence is newer than any accepted frame for the cycle.

SHIZUKU TIMESTAMP RULE
Current Shizuku capture returns Bitmap only. Generation 2 should preserve enough metadata to prove timing. Minimum safe rule before a true capture timestamp exists:
- requestStartedUptimeMs must be >= closeCycleStartedUptimeMs;
- completion must be >= request start;
- exact current serviceEpoch/cycleId required.
A request already in flight before the cycle is not allowed to become a continuity frame solely because it completed after cycle start.

FRAME BIND RULE
DisplayMirrorHost may bind a frozen frame only if ContinuityFrameLeaseStore returns a FrameLease for the exact active closeCycleId. If not, the host follows the existing fallback path. Never silently substitute a previous-cycle generic cache frame.

FRESHNESS RULE
Keep the current 10,000 ms maximum age initially as a SECONDARY bound. The correctness improvement comes from provenance, not from inventing a new age constant.

CYCLE INVALIDATION
On reversal/native takeover/destroy:
- invalidate active closeCycleId;
- make late capture publication inert;
- drop the eligible continuity-frame reference;
- do not clear the generic SnapshotCache unless required for unrelated reasons.

CAPTURE COALESCING / PERFORMANCE
P0 correctness does not require a second screenshot if existing PanelEngine capture can publish a proven current-cycle frame. However capture ownership must be explicit.
Recommended integration:
- expose current frame-cycle token to the capture path;
- if a capture begins after cycle arming, tag it with that token;
- Accessibility result may use exact ScreenshotResult.timestamp to prove eligibility;
- if capture began before arming and cannot prove post-arm sampling, it may still serve PanelEngine’s visual overlay but must not be promoted to continuity frozen-frame authority.

Optional P1 optimization:
Add a small shared capture broker so the continuity consumer can request one current-cycle capture without duplicating a PanelEngine capture that is already proven eligible.

EXPLICIT INVARIANTS
1. A frozen continuity frame belongs to exactly one serviceEpoch + closeCycleId.
2. Starting a new close cycle never inherits frozen-frame authority from the previous cycle.
3. A bitmap’s age alone can never authorize continuity presentation.
4. Controller state generation and frozen-frame closeCycleId are distinct identities.
5. A capture completed after reversal cannot become eligible for the reversed cycle.
6. A capture from a prior service/process epoch is inert.
7. Accessibility capture time must come from ScreenshotResult.timestamp when available, not callback-receipt time.
8. Shizuku captures without exact capture timestamps must fail closed if their request began before the cycle.
9. Logical display IDs are never used as permanent physical identity.
10. No hinge threshold changes are part of this proposal.
11. No raw physical-panel OFF command is part of this proposal.
12. If no exact-cycle frozen frame exists, use an existing safe fallback; do not replay unproven prior content.
13. Transition Lab timestamps frame events at the event boundary, not retrospectively.

DEGRADATION PATH
- No eligible frame: current live-mirror fallback or Samsung-native behavior, depending surrounding readiness/privilege state.
- Shizuku unavailable: Accessibility capture may still publish exact-timestamp frame; otherwise fallback.
- Secure capture failure: no current-cycle frozen frame is authorized. Prior non-secure cache content is not promoted solely due to age.
- Service restart: old epoch frames are rejected; continuity reconstructs from new lifecycle.

13. REGRESSION RISKS
==================================================

CORRECTNESS REGRESSIONS
- Incorrect closeCycleId lifecycle could reject legitimate current-cycle frames or accidentally span separate closes.
- Using controller.generation directly would be wrong because it changes within one close cycle.
- Bad serviceEpoch plumbing could cause all captures to reject after reconnect/restart.

LATENCY REGRESSIONS
- Metadata checks themselves are local/O(1) and should be negligible, but unmeasured.
- Fail-closed selection can increase live-mirror fallback frequency, whose startup latency is device-dependent and UNKNOWN.
- Do not add a mandatory second screenshot to the transition critical path without measurement.

POWER IMPACT
- P0 provenance checks require no additional capture, Binder call, or panel power operation.
- An optional capture-broker retry/second capture could increase power and should be separately justified.

SAMSUNG INTERFERENCE
- No Samsung panel-power or topology behavior is changed by P0.
- Shizuku capture timing remains platform-specific; do not infer pixel sample time from callback arrival.

LIFECYCLE REGRESSIONS
- Frame cycle invalidation must run on destroy/reversal/native takeover.
- Old service/process capture results must not repopulate the store.

RACE INTRODUCTION
- If capture publication and cycle invalidation happen on different threads, store access needs single-thread confinement or synchronization.
- Recommended: confine ContinuityFrameLeaseStore mutation to the existing app handler/main orchestration boundary, or make acceptance atomically synchronized.

RENDERING REGRESSIONS
- If no frame is eligible, existing live mirror may reveal different visual characteristics than frozen continuity.
- Secure content behavior of live mirror remains device/platform-specific and must be tested; never re-enable stale cached content to mask a black/secure fallback.

SERVICE-RESTART BEHAVIOR
- New serviceEpoch intentionally invalidates old frame authority.
- Recovery should prefer a fresh current-cycle capture or native/live fallback.
