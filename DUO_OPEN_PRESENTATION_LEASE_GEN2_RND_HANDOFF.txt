1. EXECUTIVE SUMMARY
==================================================

SUBSYSTEM CHOSEN
Fold7 first-visible-frame / compositor-presentation ownership for continuity content, spanning DisplayMirrorHost frozen View/Canvas rendering, the live SurfaceControl mirror path, and Transition Lab transaction/presentation telemetry.

WHY CURRENT main MADE THIS THE HIGHEST-VALUE TARGET
CURRENT main already contains or has imported deep work in three immediately adjacent areas:
1. Cover Lease Protocol Gen2: privileged cover mutation authority and ordered app↔shell snapshot identity.
2. Cover Readiness Gen2: proof that the leased cover route is topologically/display-state ready to host continuity content.
3. Frozen Frame Provenance Gen2: proof that a frozen bitmap belongs to the current physical close cycle.

Those solve, or propose to solve, “who owns the panel?”, “is the destination ready?”, and “are these pixels authorized for this fold?” They do not own the final question: “did THIS exact authorized content attempt actually reach Android’s presentation boundary?”

CURRENT 1.3.29 has two asymmetric rendering paths:
- FROZEN_VIEW is the preferred deterministic Fold7 path. tryBindFrozenFrame() sets the bitmap, makes the child View VISIBLE, calls invalidate(), logs that the frozen frame was bound, and returns true. It has no frame-commit or transaction-presented identity.
- LIVE_MIRROR uses SurfaceControl geometry and Transition Lab transaction callbacks, but those callbacks are observational only. SurfaceTransactionProbe.Token contains transactionSequence + nearest vsyncId, not the fold/controller generation, host lifetime, content/frame lease, or presentation attempt identity. TransitionLab.recordTransaction() correlates the callback with latestHingeSample at callback time.

DOMINANT LIMITATION
Presentation is currently an unowned terminal side effect. The frozen path can report binding success before any proof that a frame containing the target bitmap was rendered/submitted/presented. The live path can measure transaction presentation, but the transaction callback is not end-to-end correlated to the immutable fold/content/host attempt that created it. A late callback therefore cannot be proven to belong to the currently active continuity attempt from the callback token itself.

GENERATION-2 DIRECTION
Introduce a small, deterministic Presentation Lease owner with immutable identity:
- serviceEpoch;
- closeCycleId;
- hostEpoch;
- contentLeaseId;
- attemptSequence;
- path = FROZEN_VIEW | LIVE_MIRROR.

For FROZEN_VIEW:
- record that the intended content actually participated in onDraw;
- register ViewTreeObserver.registerFrameCommitCallback for the attempt;
- queue a visually inert, identity-bearing SurfaceControl marker transaction with AttachedSurfaceControl.applyTransactionOnDraw();
- add transaction committed/completed listeners to the marker transaction;
- confirm the presentation attempt only when DRAW + FRAME_COMMITTED + TRANSACTION_PRESENTED all belong to the same current identity.

For LIVE_MIRROR:
- reuse the existing SurfaceControl geometry transaction as the presentation transaction;
- carry immutable PresentationIdentity into the production callback path;
- transaction completion/presentation confirms only that exact current attempt.

No fixed delay, sleep, hinge-threshold change, task movement, panel-power change, or new subprocess is proposed.

STRONGEST EVIDENCE
1. CURRENT DisplayMirrorHost.tryBindFrozenFrame() returns success immediately after VISIBLE + invalidate() with no frame-commit/present callback.
2. CURRENT DisplayMirrorHost.applyGeometry() instruments the LIVE_MIRROR SurfaceControl transaction, but the preferred FROZEN_VIEW Canvas path does not go through that transaction instrumentation.
3. CURRENT SurfaceTransactionProbe.Token has only transactionSequence and vsyncId; it does not carry controller generation, host identity, content identity, or close-cycle identity.
4. CURRENT TransitionLab.recordTransaction() reads latestHingeSample when the callback arrives, not immutable transition/presentation identity captured when the transaction was created.
5. A source-faithful reduced baseline model reproduces “bound=true with zero presentation proof” and “late callback attributed to newer current generation.”
6. The Generation-2 pure Kotlin presentation-lease model compiled and passed 23/23 deterministic tests, including all 24 callback-order permutations, close→open→close stale-completion fencing, a 1,000-callback duplicate storm, and a fixed-seed 100,000-operation fuzz run.
7. Android’s public ViewTreeObserver.registerFrameCommitCallback contract reports when current rendering content has been rendered and submitted to the swap chain, while explicitly stating that it may not yet be visible.
8. Android’s public AttachedSurfaceControl.applyTransactionOnDraw contract states that the supplied transaction is merged with the ViewRoot buffer transaction and shown atomically synchronized with the next draw.
9. Android’s public SurfaceControl.Transaction.addTransactionCompletedListener contract states that the listener is invoked when the transaction is presented.

CONFIDENCE LEVEL
HIGH for the source-level ownership/observability gap and the deterministic model properties.
MEDIUM for the marker-transaction integration approach until Android project compilation and Fold7 runtime traces prove it behaves as intended in this accessibility-overlay ViewRoot.
LOW/UNKNOWN for any claim that this is presently causing a user-visible Fold7 glitch. No device trace in this silo establishes that.

LARGEST REMAINING UNKNOWN
The exact timing relationship on the physical Galaxy Z Fold7 among View onDraw, frame-commit callback, marker transaction commit/completion, present-fence signal, and photons visible on the cover. Framework presentation evidence is not proof of physical photons; external high-frame-rate video remains required.

CURRENT CAUSAL PATH — FROZEN VIEW
PHYSICAL HINGE
→ controller reaches COVER_VISUAL
→ coordinator ShowMirror
→ syncMirrorHost()
→ current topology resolves active inner + active cover
→ construct DisplayMirrorHost
→ WindowManager.addView(hostView)

QUEUE / RACE BOUNDARIES — FROZEN VIEW
- main Handler / View attach scheduling;
- bind() posted after attachment;
- View invalidation does not itself prove the target draw has completed;
- RenderThread / BufferQueue / SurfaceFlinger are asynchronous downstream boundaries;
- no PresentationIdentity follows this path;
- detach/reversal can occur before downstream callbacks that would theoretically describe the earlier draw.

CURRENT FROZEN SUCCESS SEMANTIC
tryBindFrozenFrame() returns true immediately after VISIBLE + invalidate(). It does not wait for or observe:
- frozenPaneView.onDraw for this specific content lease;
- View frame commit;
- ViewRoot buffer submission identity;
- SurfaceFlinger transaction presentation;
- present fence;
- physical photons.

CURRENT frozenPaneView.onDraw()
drawFrozenFrame(canvas) reads the mutable frozenFrame field and draws it. It carries no closeCycleId/contentLeaseId/presentation attempt identity and emits no presentation milestone.

CURRENT CAUSAL PATH — LIVE MIRROR

→ shell returns SurfaceControl mirror
→ hostView.post completion
→ stale local generation check
→ appMirror = mirror
→ applyGeometry()
→ build root reparent transaction or new SurfaceControl.Transaction
→ hidden setGeometry reflection
→ set layer/alpha/visibility
→ TransitionLab.instrumentTransaction(transaction)
→ root.applyTransactionOnDraw(transaction)
→ TransitionLab.markTransactionSubmitted(token, accepted)
→ hostView.invalidate()
→ SurfaceTransactionProbe committed/completed callbacks in FULL_LAB
→ TransitionLab.recordTransaction()

CURRENT LIVE TRANSACTION TOKEN
SurfaceTransactionProbe.Token contains:
- transactionSequence
- vsyncId

It does NOT contain:
- controller generation;
- closeCycleId;
- mirror host epoch;
- mirror lease/content lease in the token;
- service epoch;
- path identity;
- immutable hinge sample sequence captured as ownership identity.

CURRENT TELEMETRY CORRELATION
TransitionLab.recordTransaction(record) obtains:
  val hinge = latestHingeSample
at callback-recording time, then writes the event with that latest hinge context. This is useful observational telemetry but cannot independently prove that a late callback belongs to the latest fold state/content attempt.

CURRENT HOST USABILITY SEMANTIC
DisplayMirrorHost.isUsable = attached && hostView.isAttachedToWindow.
This proves the host window is attached; it does not mean the desired continuity content has been presented.

CURRENT COORDINATOR SEMANTIC
The coordinator tracks mirrorRequested, mirrorGeneration and mirrorHost. It does not maintain presentation states such as DRAW_PENDING, FRAME_COMMITTED, PRESENTED, CANCELLED, or PRESENTATION_UNCONFIRMED.

OPENING / REVERSAL
Controller generation and DisplayMirrorHost local generation already fence several stale shell/live-mirror completions. PresentationLease does not replace those checks. It extends ownership through the later draw/commit/present callbacks that current production does not model.

SERVICE / PROCESS RESTART
Current host state is in-process and disappears with service/process restart. Transition Lab callbacks already queued on another executor can still be conceptually late relative to newer context; current transaction token itself does not encode service epoch.

FALLBACK
Frozen path falls back to live mirror only when no acceptable frozen frame is bound. No proposal here changes Samsung-native fallback, panel power, route ownership, or user task placement.

7. HYPOTHESES / UNVERIFIED RISKS
==================================================

H1 — FROZEN BIND→FIRST PRESENT LATENCY IS MATERIAL
Hypothesis: the gap between tryBindFrozenFrame() returning true and actual presentation sometimes spans enough time to matter during rapid close/reversal.
Experiment: timestamp bind start, onDraw, frame commit, transaction commit/completed, present-fence signal and external first-visible frame for 100 closes at multiple speeds.

H2 — LATE CALLBACK MISATTRIBUTION OCCURS IN REAL TRANSITION LAB EXPORTS
Hypothesis: executor/callback latency can cause a transaction callback created under fold attempt N to be recorded after latestHingeSample/controller context has advanced to N+1.
Experiment: inject callback executor delay; add immutable attempt identity; compare old “latest context” attribution versus token identity.

H3 — INVISIBLE MARKER TRANSACTION COMPLETION TRACKS THE SAME VIEWROOT FRAME
Hypothesis: an app-owned hidden marker SurfaceControl, reparented to the attached ViewRoot and mutated in a transaction queued with applyTransactionOnDraw, produces commit/completed callbacks for the same ViewRoot draw containing the frozen bitmap.
Experiment: alternate obvious test patterns/content IDs; compare onDraw identity, frame commit, marker callbacks, PixelCopy/debug capture, and external video.

H4 — COMPLETED CALLBACK MAY OCCUR WITHOUT A VALID PRESENT-FENCE SIGNAL TIMESTAMP
Hypothesis: transaction-completed callback remains useful presentation evidence even when TransactionStats.presentFence is invalid or signal timestamp unavailable.
Experiment: record completed callback count, presentFence validity and signal timestamps across 500 transitions.

H5 — FRAME COMMIT CALLBACK COULD BE ABSENT UNDER AN ABNORMAL NON-HARDWARE-RENDERED HOST
Hypothesis: production Fold7 accessibility overlay is always hardware rendered because the window requests FLAG_HARDWARE_ACCELERATED, but the API contract states frame-commit callback does nothing without hardware rendering.
Experiment: record View.isHardwareAccelerated / callback receipt; degradation must remain PRESENTATION_UNCONFIRMED rather than blocking content.

H6 — PRODUCTION RECOVERY SHOULD NOT WAIT FOR PRESENTATION ACK
Hypothesis: gating actual visibility on callback receipt would add unnecessary latency/risk; callbacks should establish ownership/telemetry and enable later recovery policies, not hold back the first draw.
Experiment: A/B device test with observation-only PresentationLease first; only add recovery behavior if traces prove a missing-present failure mode.

8. GENERATION-2 DESIGN
==================================================

DESIGN NAME
Presentation Lease Gen2 — Attempt-Scoped Draw/Commit/Presented Ownership.

RESPONSIBILITIES
A. Fold7ContinuityController remains owner of fold intent, thresholds, direction and transition generation.
B. Cover Lease Protocol remains owner of privileged panel mutation authority.
C. Cover Readiness remains owner of destination readiness.
D. Frozen Frame Provenance remains owner of frozen content authorization and closeCycleId/contentLeaseId.
E. NEW PresentationLeaseStore owns the evidence that an exact content/host attempt reached the framework presentation boundary.
F. DisplayMirrorHost owns platform binding of View/SurfaceControl evidence to PresentationLeaseStore.
G. Transition Lab records immutable presentation identity rather than reconstructing ownership from latest mutable context.

PRESENTATION IDENTITY
PresentationIdentity {
  serviceEpoch
  closeCycleId
  hostEpoch
  contentLeaseId
  attemptSequence
}

PATH
PresentationPath {
  FROZEN_VIEW
  LIVE_MIRROR
}

PROPOSED PRESENTATION PHASES
- NONE
- ATTEMPT_STARTED
- DRAW_OBSERVED (frozen only)
- FRAME_COMMITTED (frozen only)
- TRANSACTION_COMMITTED
- TRANSACTION_PRESENTED
- PRESENTATION_CONFIRMED
- PRESENTATION_UNCONFIRMED
- CANCELLED/STALE

Do not require callback arrival ordering. Store facts idempotently and evaluate the invariant set.

FROZEN_VIEW CONFIRMATION PREDICATE
PRESENTATION_CONFIRMED only if all are true for the exact current PresentationIdentity:
- drawObserved == true;
- frameCommitted == true;
- transactionPresented == true;
- attempt not cancelled;
- serviceEpoch current;
- hostEpoch current;
- closeCycleId current;
- contentLeaseId current.

TRANSACTION_COMMITTED is useful latency evidence but is NOT sufficient for PRESENTATION_CONFIRMED.

LIVE_MIRROR CONFIRMATION PREDICATE
The live mirror pixels are controlled by the SurfaceControl transaction itself. For a current attempt:
- transactionPresented == true;
- attempt not cancelled;
- exact PresentationIdentity current.
No View frame-commit proof is required for LIVE_MIRROR.

FROZEN MARKER TRANSACTION
1. Create/reuse one app-owned SurfaceControl marker for the host.
2. Keep it visually inert/hidden.
3. Reparent it to the current AttachedSurfaceControl root using buildReparentTransaction or equivalent safe setup.
4. For each frozen presentation attempt, build a small marker transaction containing a harmless marker mutation plus committed/completed listeners that close over immutable PresentationIdentity.
5. Queue it with hostView.rootSurfaceControl.applyTransactionOnDraw(transaction).
6. Register frame-commit callback before invalidating frozenPaneView.
7. In frozenPaneView.onDraw, record the exact current draw identity only after drawing the expected content lease.
8. On completed callback, record presentation for that identity. If present fence is valid, record signal timestamp separately.

The marker transaction must not manipulate Samsung physical display state, task state, user app surfaces, or privileged shell ownership.

CALLBACK THREADING
- View onDraw: UI/View render scheduling context.
- frame-commit callback: framework invokes after rendering submission; callback code must stay tiny and hand off to the main/owner thread if needed.
- transaction callbacks: dedicated existing transaction executor is acceptable.
- mutation of PresentationLeaseStore should either be thread-safe or serialized onto one owner thread. Preferred production design: callback captures immutable event and posts to one coordinator/host owner Handler; pure model remains thread-agnostic.

CANCELLATION / STALE CALLBACKS
Never try to “unsend” already submitted SurfaceFlinger work. Instead invalidate authority immediately and make late callbacks inert.
Invalidate presentation attempt on:
- opening reversal;
- native cover takeover;
- mirror host detach;
- mirror host replacement/logical remap;
- content frame lease replacement;
- FROZEN_VIEW↔LIVE_MIRROR path switch;
- service destruction;
- service/process epoch change.

DEGRADATION
- Do not delay rendering while waiting for evidence.
- If marker transaction cannot be constructed/submitted, render through current path and mark PRESENTATION_UNCONFIRMED.
- If frame commit callback never arrives, do not falsely mark PRESENTED.
- If transaction completed callback is unavailable, preserve content but mark proof degraded.
- Samsung-native behavior remains fallback when privileged continuity infrastructure is unavailable.

TRANSITION LAB EXTENSION
Every presentation event should include immutable:
- serviceEpoch;
- closeCycleId;
- hostEpoch;
- contentLeaseId;
- attemptSequence;
- path;
- controller generation as diagnostic (not the only identity);
- source display physical/logical facts;
- destination display physical/logical facts;
- drawNs;
- frameCommitNs;
- transactionSubmitNs;
- transactionCommitNs;
- transactionCompletedCallbackNs;
- presentFenceSignalNs if valid;
- staleAtCallback;
- cancellationReason.

Do not replace captured identity with latestHingeSample at callback time. Latest hinge can remain an additional observation field.

EXPLICIT INVARIANTS
1. No presentation callback may mutate an attempt with a different PresentationIdentity.
2. An operation from serviceEpoch N cannot confirm serviceEpoch N+1.
3. A hostEpoch N callback cannot confirm a replacement hostEpoch N+1.
4. A contentLeaseId N callback cannot confirm replacement contentLeaseId N+1.
5. A prior closeCycleId cannot confirm the next physical close.
6. FROZEN_VIEW cannot be PRESENTATION_CONFIRMED without drawObserved.
7. FROZEN_VIEW cannot be PRESENTATION_CONFIRMED without frameCommitted.
8. Neither path can be PRESENTATION_CONFIRMED without transactionPresented.
9. transactionCommitted is not transactionPresented.
10. Duplicate callbacks are idempotent.
11. Callback order is not assumed.
12. Cancellation makes all later callbacks for the attempt observational-only/stale.
13. Presentation instrumentation must not add sleeps or change hinge thresholds.
14. Presentation confirmation is framework evidence, not physical-photon proof.
15. Logical display ID is never stable physical identity.
16. Current user task remains on Android’s normal/default display architecture.
17. No raw physical panel OFF command is introduced.

13. REGRESSION RISKS
==================================================

CORRECTNESS REGRESSIONS
- If closeCycleId/contentLeaseId wiring is wrong, valid callbacks may be discarded.
- If PresentationIdentity is derived from controller.generation alone, the design loses its intended cross-subsystem separation.
- If frame-commit callback is registered for the wrong draw, proof could be associated incorrectly; exact attempt identity and onDraw evidence are mandatory.

LATENCY REGRESSIONS
- Gen2 must not wait before drawing. If an implementation accidentally gates visibility on callback receipt, it could add one or more frames of latency. That is explicitly not proposed.
- Marker transaction setup adds some CPU/object overhead; magnitude is UNKNOWN and should be measured.

POWER IMPACT
- Expected low if one marker transaction per first presentation attempt. Actual impact UNKNOWN.
- Do not register continuous presentation listeners beyond active transition windows.

SAMSUNG INTERFERENCE
- No Samsung panel state is mutated by the marker design, but OEM compositor behavior/timing is unverified.

LIFECYCLE REGRESSIONS
- Marker SurfaceControl must be released with host detach/service destruction.
- Frame commit callback may already be pending; identity must make it inert if unregister cannot remove it.

RACE INTRODUCTION
- Callbacks arrive on different threads/executors. Do not mutate an unsynchronized PresentationLeaseStore from arbitrary threads in production. Serialize onto owner Handler or implement thread safety.

RENDERING REGRESSIONS
- Marker must remain visually inert. No visible buffer/content should be attached to it.
- Do not alter root View surface alpha/crop/position as part of initial implementation.

SERVICE-RESTART BEHAVIOR
- All old serviceEpoch tokens must be rejected after restart.

INSTRUMENTATION REGRESSION
- Do not replace existing Transition Lab transaction sequence/vsync fields; extend them with immutable presentation identity.
