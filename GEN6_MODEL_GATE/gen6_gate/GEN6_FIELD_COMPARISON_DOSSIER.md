## Comparison conclusions

The strongest trace-backed opening delay is currently the **software wait before action**, not the shell wake command itself: in the Gen4 field sample, leave-closed hints preceded the first nonzero angle by a median ~810 ms while the shell wake itself had a median ~161 ms. Gen6 therefore keeps hinge geometry semantic/real but permits a separate wake/visual attempt to start from a corroborated leave-closed hint.

The raw Transition Lab proves that frame-presentation metadata is already available on the device. Its measured ~60 Hz cadence also demonstrates why a 120 Hz request must be treated as optional and verified from frame timestamps rather than inferred from `Display.mode`.

The Gen5 V2 model remains a useful phase-improvement reference, but it is not directly comparable to Gen6's wake-hint-to-presentation-opportunity replay. One is angular/phase model error on selected moving segments; the other measures the opportunity to start presentation after a device-state hint. They should remain separate until the same script is run on a Gen6 APK.

## Evidence still missing for a true Gen5-vs-Gen6 physical comparison

A raw Gen5 Beta1 physical diagnostic bundle matching the handoff's sampled 0.6–4.0 s opening delay and 154–327 ms wake range was not located in current AgentBus Library or the scoped Gmail diagnostic search. Gen6 therefore must not claim a physical latency win over Gen5 Beta1 yet. The next physical candidate should capture the same typed timing fields on identical slow/normal/fast and 30–70° reversal scripts.
