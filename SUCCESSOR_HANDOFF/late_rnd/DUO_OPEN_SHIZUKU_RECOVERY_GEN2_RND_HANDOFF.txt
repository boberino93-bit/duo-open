8. GENERATION-2 DESIGN

Design name=PrivilegeEpochRecoveryGate

Responsibilities:
A. App recovery authority
- Treat every ShizukuBridge.connectionEpoch change away from Ready as an authority revocation.
- Immediately invalidate cover readiness, accepted shell token, in-flight prewarm, presentation/mirror visual authority, and any privileged action generation associated with the old epoch.
- Do not let controller state names implying readiness remain authoritative after the evidence they depended on is invalid.

B. Controller integration
Preferred minimal integration:
- Add a dedicated coordinator-level recovery state/gate rather than mixing shell lifecycle semantics into normal hinge CAS logic.
- On privilege loss, revoke mirrorRequested and hide/release local visual host authority immediately.
- Invalidate/cancel current privileged close-cycle side effects or mark the cycle RECOVERY_REQUIRED.
- Controller must not emit ShowMirror while recoveryRequired=true.
- On reconnect, do NOT infer old COVER_READY_HIDDEN as valid. Reconstruct from current hinge/topology only after shell recovery succeeds, then perform a fresh prewarm/readiness proof if the close still needs cover ownership.

C. Shell recovery authority
- Graceful SHIZUKU_DESTROY: drain the exact known Fold7CoverPanelLease on coverMutationExecutor before executor shutdown/System.exit.
- Never use raw physical OFF.
- If native cover is authoritative, clear lease with no power mutation.
- If inner is default and a fresh secondary cover logical route maps safely, use framework logical power reset.
- Bound cleanup time; record whether lease reached IDLE before exit.

D. Cold-start recovery fence
- A new DuoShellService must not silently begin IDLE from the perspective of cover safety.
- Before the first V3 cover mutation, initialize recovery as UNKNOWN_RECOVERY and reconcile fresh topology.
- If native cover: recovery complete → IDLE.
- If safe non-default cover route: framework-reset logical cover → IDLE on success.
- If topology cannot prove a safe recovery action: remain UNKNOWN_RECOVERY and reject/defer new prewarm.
- Do not let current beginPrewarm(UNKNOWN_RECOVERY) semantics erase unresolved recovery evidence; change this behavior or interpose a gate so UNKNOWN_RECOVERY cannot start a new physical wake until resolved.

E. Epoch and stale results
- Existing app connectionEpoch checks remain.
- Add privilegeEpoch/recoveryEpoch to any app-side recovery callbacks so old reconnect/recovery completions cannot revive a newer transition.
- ShellSession change is authoritative evidence of a new daemon process.

F. Degradation
- If Shizuku is unavailable: return visual ownership to non-privileged/native behavior; never claim privileged cover readiness/visibility.
- If recovery cannot prove safe ownership: fail closed on privileged prewarm; allow Samsung/native handoff.

Core invariants:
1. visualMirrorActive => ShizukuBridge.ready && current privilegeEpoch && coverReadiness==READY.
2. COVER_READY_HIDDEN cannot remain authoritative across privilegeEpoch change.
3. ShowMirror requires readiness evidence produced in the same privilegeEpoch/shellSession authority domain.
4. New daemon may not start a new cover mutation while UNKNOWN_RECOVERY is unresolved.
5. Graceful destroy attempts framework-safe lease drain before process exit.
6. No raw physical-panel OFF command is introduced.
7. Old daemon/session callbacks are inert after connectionEpoch change.
8. Recovery may restore native ownership, but must never infer exact old physical ownership after process loss.

12. BASELINE VS GENERATION-2

Baseline:
- Connection epoch protects async result freshness.
- Readiness can be invalidated independently of controller state.
- Controller readiness states can survive privilege loss.
- UserService destroy does mirror cleanup only.
- New daemon starts cover lease model IDLE.

Gen2:
- Connection epoch becomes a full authority epoch boundary.
- Ready/visual controller authority cannot survive loss of its evidence.
- UserService destroy drains cover ownership when safely possible.
- New daemon starts behind a recovery fence, not a blind IDLE assumption.
- Fresh shell recovery + fresh cover readiness are prerequisites for resumed visible ownership.

13. REGRESSION RISKS

Correctness:
- Over-aggressive privilege-loss reset could prematurely abandon a close transition that would otherwise recover seamlessly.
- Recovery must not accidentally issue reset against the native/default cover.

Latency:
- Reconnect path adds one recovery/revalidation gate before prewarm/visual. Expected cost UNKNOWN; measure on device.
- Normal no-loss path should have near-zero added cost if gate is epoch-stable.

Power:
- Failing closed may leave Samsung native behavior rather than keeping a prewarmed cover route; preferable to unowned mutation.
- Cleanup must remain framework logical reset only; no raw OFF.

Samsung interference:
- Topology can remap during recovery. Every logical ID must be freshly resolved and immediately validated.

Lifecycle:
- Graceful destroy is best-effort; abrupt Shizuku death may bypass the destroy cleanup path. Cold-start recovery remains mandatory.

Races:
- Reconnect, topology callbacks, and hinge motion can cross. recoveryEpoch/connectionEpoch must gate every completion.

Rendering:
- Clearing mirrorRequested on loss may expose native/generic rendering earlier; validate for flashes.

Restart behavior:
- Do not preserve stale controller ready/visual state across shellSession changes.
