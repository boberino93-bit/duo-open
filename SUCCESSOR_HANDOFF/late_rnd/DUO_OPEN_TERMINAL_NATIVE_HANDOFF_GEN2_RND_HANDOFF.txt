1. EXECUTIVE SUMMARY
======================================================================

This workstream isolates the terminal CLOSED-side handoff from Duo's visible
cover visual to Samsung/native cover steady state.

Source-confirmed gap on current main:
- Fold7ContinuityController.Topology.nativeCover means only:
    coverActive && coverIsDefault && !innerActive
- At <= NATIVE_COVER_MAX_DEG (12 degrees), that topology immediately drives
  COVER_VISUAL -> NATIVE_COVER.
- The transition emits HideMirror + ReleaseSecondary.
- Fold7Gen2Kernel simultaneously invalidates the exact close cycle, frozen frame,
  and cover readiness when NATIVE_COVER is entered.
- Fold7ContinuityCoordinator.hideMirror() detaches DisplayMirrorHost immediately.
- DisplayMirrorHost.detach() invalidates presentation identity, clears the frozen
  frame, releases the mirror and removes the overlay window immediately.

There is no destination/native-frame presentation acknowledgement in that path.
Therefore the current architecture can causally tear down Duo's final cover frame
as soon as logical/power topology says the native cover owns the display, even if
the first native steady-state composition has not yet visually landed.

This is a source-confirmed ordering gap. Whether it creates a visible flash/jump
on every physical Fold7 close is DEVICE-UNVERIFIED.

Proposed Gen3 correction:
- add a terminal SamsungNativeHandoffOwner / landing lease after current visual
  ownership and presentation ownership;
- treat native topology as ADMISSION, not presentation proof;
- retain the exact current Duo visual and exact-cycle content while native topology
  stabilizes;
- use API 35+ SurfaceControl.Transaction.addTransactionCompletedListener presentation
  callbacks as compositor landing barriers;
- after the configured landing barriers, submit an exact fade-to-native transaction;
- only after the fade transaction itself is presented may the close cycle/content,
  Duo host, and privileged secondary lease be released as CLEAN;
- reversal, topology loss, host replacement, service restart, or a newer visual
  attempt cancels the old terminal handoff token;
- watchdog escape is explicitly DEGRADED_TIMEOUT, never mislabeled clean.

Pure Kotlin model result: 11/11 focused tests PASS + 100,000 deterministic adversarial
events PASS. The first adversarial run exposed a test-harness invariant bug; that
failure is preserved rather than erased.

F. Already-existing stronger presentation primitive
DisplayMirrorHost already uses API 35+:
- SurfaceControl.Transaction.addTransactionCompletedListener(...)
- TransactionStats.presentFence
for LIVE_MIRROR presentation instrumentation.

Android public API contract:
- addTransactionCommittedListener: transaction applied / updates ready to be
  presented; NOT proof that it has been presented.
- addTransactionCompletedListener (API 35): callback invoked when transaction is
  presented.
- TransactionStats.getPresentFence(): fence signals when transaction has been
  presented; empty fence may be returned on devices without present-fence support.

Official references:
https://developer.android.com/reference/android/view/SurfaceControl.Transaction
https://developer.android.com/reference/kotlin/android/view/SurfaceControl.TransactionStats

6. CONFIRMED FINDINGS
======================================================================

1. Current endpoint ownership is overloaded: logical native-route ownership is treated
   as sufficient permission to tear down the last visual cover.

2. Current close-cycle invalidation timing makes delayed terminal validation impossible:
   by the time NATIVE_COVER is entered, the exact frame/readiness lifetime is already
   invalidated.

3. A clean terminal protocol therefore needs a PENDING terminal state/lifetime, not
   merely a delayed hide call after NATIVE_COVER.

4. The project already has the correct platform class of primitive for a compositor
   barrier on Android 16: transaction-completed/presentation callback. A new hidden
   API is not required for this concept.

5. The terminal handoff token must be built from service-stable Gen3 identities. Current
   DisplayMirrorHost-local epoch/attempt counters are insufficient as global identity.

8. PROPOSED GEN3 DESIGN
======================================================================

Recommended owner:
  SamsungNativeHandoffOwner (or TerminalNativeHandoffOwner)

Identity:
  serviceEpoch
  closeCycleId
  transitionGeneration / movement identity
  hostLeaseId            [SERVICE-STABLE from Gen3 visual/presentation owner]
  visualAttemptId        [SERVICE-GLOBAL monotonic attempt identity]
  handoffSequence        [terminal-owner monotonic attempt]

Suggested states:
  IDLE
  VISUAL_ACTIVE
  NATIVE_PENDING
  FADING_TO_NATIVE
  RELEASED_CLEAN
  RELEASED_DEGRADED_TIMEOUT

Admission:
- controller detects native topology near closed endpoint using existing policy;
- do NOT enter steady NATIVE_COVER yet;
- do NOT invalidate close cycle/frame/readiness yet;
- do NOT hide/detach/release secondary yet;
- enter NATIVE_PENDING and retain exact current opaque Duo terminal visual.

Landing barriers:
- submit a draw-synchronized/no-op-or-alpha=1 SurfaceControl transaction on the exact
  current visual host/root;
- attach addTransactionCompletedListener;
- completion is the minimum evidence that counts as a PRESENTED barrier;
- valid present-fence timestamp upgrades evidence quality/timing but is not required
  for the API's presented callback itself;
- repeat for configured barrier count;
- prototype uses 2 barriers ONLY as a MODELED starting safety floor, not a field-tuned
  production constant.

Fade:
- after required barriers, native topology still must be current/stable;
- submit exact overlay fade-to-native transaction;
- clean release is forbidden until that fade transaction completes as PRESENTED;
- after fade-presented:
    1. mark terminal handoff CLEAN;
    2. transition to steady NATIVE_COVER;
    3. invalidate close cycle/frame/readiness;
    4. detach/release Duo visual host;
    5. release privileged secondary display lease.

Cancellation:
Any of these invalidate the terminal token and retain/rebind visual ownership as needed:
- opening reversal;
- native topology loss;
- new movement/close cycle;
- host replacement/remap;
- new visual attempt;
- service epoch change;
- Shizuku authority epoch loss.
Old barrier/fade callbacks become inert.

Watchdog:
- bounded escape is required to prevent a permanently opaque overlay if presentation
  callbacks fail;
- timeout value MUST come from Fold7 measurements;
- watchdog release is RELEASED_DEGRADED_TIMEOUT with explicit diagnostics;
- never call timeout a clean native handoff.

Fallback evidence:
- On target Android 16, transaction-completed should be the primary barrier.
- If present fence is empty but transaction-completed fires, record PRESENTED_CALLBACK
  evidence and continue according to field-validated policy.
- Transaction-committed alone must not be upgraded to presented.

13. REGRESSION RISKS
======================================================================

R1. Lingering overlay if terminal callbacks never arrive.
Mitigation: bounded, explicitly degraded watchdog; strong diagnostics.

R2. Added terminal latency.
Mitigation: presentation-count policy rather than arbitrary long sleep; field-tune number
of barriers and fade duration using TransitionLab.

R3. Reversal during pending/fade.
Mitigation: exact identity invalidation and restore/rebind current visual authority.

R4. Host remap after admission.
Mitigation: service-stable hostLeaseId/visualAttemptId; old token inert; new owner decides
whether to restart terminal handoff.

R5. Native content differs from Duo frame.
Mitigation: outside this owner's authority; coordinate with launcher-content-continuity
workstream. Do not hide content mismatch with stale frame substitution.

R6. Releasing privileged lease changes topology after fade.
Mitigation: release only after overlay fade is presented and steady native topology is
still current; instrument post-release topology.

21. BOTTOM LINE
======================================================================

Current main knows when Samsung/native cover topology becomes logically authoritative,
but it does not know that native steady-state pixels have visually landed before it
tears Duo down.

The clean architectural fix is not another angle threshold or arbitrary sleep. It is a
short exact-identity terminal landing lease: hold the final Duo frame, cross one or more
presentation-completed compositor barriers, present the fade to native, then release
visual/content/secondary lifetimes in that order.

The pure ownership model is strong under adversarial sequencing, but the decisive next
step is physical Fold7 integration/measurement. Native-content freshness underneath the
overlay remains unproven and must not be overstated.
